# FlappyGame — 專案亮點

> 以 **Unity 6** 開發、可直接在瀏覽器遊玩的橫向捲軸遊戲。以下是我在專案中的技術決定與佐證。

---

## TL;DR

- **引擎**：Unity 6000.3.12f1（URP 17.3）、C#；約 29 支腳本、~3,100 行
- **可玩 Demo**：<https://allenh94.itch.io/flappygame>
- 三個重點：熱路徑零配置的**物件池**、手感優先的**延遲衝力**、一套角色分權的 **AI 協作流程**（真的抓到錯）

---

## 一、技術亮點

### 1. 物件池（Object Pooling）— 熱路徑零配置
水管與背景 tile 全部收斂到泛型池 `PooledActives<T>`；穩態只移動、不 `Instantiate`／`Destroy`，避免記憶體反覆分配與 GC 尖峰。內含重複 get／release 防護。

### 2. 手感設計（game feel）— 延遲到「起跳點」才施加衝力
按下**不直接給速度**，而是先播「蓄力」動畫；程式等動畫到 `normalizedTime ≥ 0.1` 才觸發 `JumpRise`、施加衝力。讓衝力對上真正的起跳點，並讓蓄力期間擋掉第二下輸入。

### 3. 遊戲狀態機（Game State Machine）
六態 `Menu / Ready / Playing / Dying / Paused / GameOver`。`Ready`、`Dying` 是為修正「開局太突兀」「死亡瞬間消失」而加的過渡態。系統改以 `GameStateAuthority` 查詢狀態，不直接持有 `GameManager`，降低耦合。

### 4. 資料驅動視差背景（Parallax Background）
`BGConfig`（ScriptableObject）驅動任意層數；深度只管速度、renderOrder 只管 sortingOrder。以 `Mathf.Repeat` 取模無縫捲動，所有 tile 位置由**同一個累計距離**推導，因此不會漂移。另附自製 Editor 即時預覽視窗。

### 5. 零依賴自製 tween 引擎（Tweening）
UI 動畫由自製 `UITween` 驅動，不引入 DOTween：手寫 easing、`LerpUnclamped` 保留過衝、token 定向停止且停止即歸位。

### 6. 手寫物理與終端速度（Terminal Velocity）
Rigidbody2D `gravityScale=0`、連續碰撞偵測，由程式每幀手動積分重力並鉗制到終端速度。為的是精準控制「終端速度 × 跳躍衝力」這個手感核心。

### 7. Editor 工具：Atlas XML 自動切圖（Sprite Slicing）
讀取素材包的 XML 自動換算座標、命名並整批寫入切片。關鍵：使用官方 `ISpriteEditorDataProvider`——因為舊的 `TextureImporter.spritesheet` 在 Unity 6000.3 已被移除。任一片越界即中止整批，不留半套結果。

### 8. 線上排行榜（Online Leaderboard）：離線也能玩
LootLocker 後端以 `ILeaderboardProvider` 隔離。讀取失敗回退快取；**送出失敗進待送佇列（上限 20、丟最舊），恢復後補送，分數不會消失**。排名以伺服器為準。附 EditMode 單元測試（注入假件）。

## 二、AI 協作工程流程（Agentic Workflow）

多代理角色分權：需求 / 架構 / 實作 / **驗收**分離，權限以設定檔 YAML **硬性強制**（驗收者只能寫報告、不能改程式）。為何要分：驗收者若能改 code，就會把不合格的東西「就地修成合格」，獨立性就沒了。

流程真的抓到錯：動畫速度被設 0 導致卡死；UI 動畫靜態驗收 PASS 卻被實測**推翻兩次**；一個實測 bug 讓架構決定**翻案重改**。

## 四、我的角色與開發方式

本專案以 **AI 協作（AI-assisted development）** 方式開發：我把 AI 當作開發工具使用，如同使用 IDE。

**我負責**：發現需求與定義規格、決策取捨與確認、實際測試與問題回報與驗收、維護 agent 的角色與權限。
**AI 負責**：協助產出架構與程式碼，並經上述驗收流程檢查、修正。
